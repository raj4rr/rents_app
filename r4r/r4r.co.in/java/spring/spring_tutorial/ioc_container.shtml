Modern Spring IoC Container

The Spring IoC (Inversion of Control) container is at the core of the Spring Framework. The container automatically creates objects, wires them together, configures them, and manages their complete lifecycle from creation until destruction. The Spring container uses dependency injection (DI) to manage the components that make up an application. These managed objects are called Spring Beans.

The Spring container gets its instructions on what objects to instantiate, configure, and assemble by reading configuration metadata. In modern Spring, this configuration metadata is provided almost exclusively via Java annotations (`@Component`, `@Service`, `@Configuration`, `@Bean`).

  1. Instantiate the application class
  2. Configure the object
  3. Assemble the dependencies between the objects
Types of Spring IoC container

Historically, Spring provided two container interfaces: BeanFactory and ApplicationContext. Today, ApplicationContext is used universally.

1. Spring BeanFactory: The root interface for accessing the Spring container. It provides basic support for DI. The legacy implementation class was XmlBeanFactory, but this has been deprecated since Spring 3.1 and should no longer be used.

2. Spring ApplicationContext: This is a sub-interface of BeanFactory. It adds more enterprise-specific functionality such as resolving textual messages from a properties file, publishing application events, and application-layer specific contexts (like WebApplicationContext). ApplicationContext is the modern standard container.

Modern Container Initialization

In a standard Java application without Spring Boot, you instantiate the container using AnnotationConfigApplicationContext:

ApplicationContext context = 
new AnnotationConfigApplicationContext(AppConfig.class);
UserService service = context.getBean(UserService.class);

Spring Boot Initialization

If you are using Spring Boot, the framework handles the creation of the ApplicationContext for you under the hood when you call SpringApplication.run():

@SpringBootApplication
public class Application {
    public static void main(String[] args) {
        ApplicationContext context = SpringApplication.run(Application.class, args);
    }
}
Approaches to Inversion of Control

Following are two approaches used to provide the Implementation of IOC:

  1. Dependency Injection (DI)
  2. Dependency Lookup (DL)

Dependency Injection (DI): Dependencies of an object are automatically satisfied by the IoC container. The object does not have to actively ask for its dependencies.

Dependency Lookup (DL): Dependencies of an object are satisfied only when the object explicitly asks the container to provide them (e.g., calling context.getBean()).

Note: Modern Spring applications rely almost entirely on Dependency Injection (DI) via constructor injection. Dependency Lookup is generally considered an anti-pattern as it couples your code to the Spring Framework API.
