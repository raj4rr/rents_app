Basic Core Concepts of Spring Framework
Previous Home Next

Spring Framework is built upon two fundamentally important core concepts:

  1. IOC (Inversion of Control) / Dependency Injection

    The basic concept of the Inversion of Control pattern (also known as Dependency Injection) is that you do not manually instantiate your objects using the `new` keyword. Instead, you describe how they should be created and what dependencies they require using Java annotations (e.g., `@Component`, `@Service`, `@Autowired`). The Spring IoC container is then responsible for instantiating the objects and injecting the required dependencies at runtime.

    Applying IoC means objects are given their dependencies by an external entity (the Spring context). This leads to loose coupling and makes your application extremely easy to unit test. In modern Spring applications, there are two primary ways dependencies are injected:

    DI TypeDescription
    Constructor Injection(Recommended by Spring) Dependencies are provided as arguments to the class constructor. This ensures the object cannot be instantiated in an invalid state and makes dependencies immutable (`final`). In modern Spring, `@Autowired` is completely optional on constructors if there is only one constructor.
    Setter/Field InjectionDependencies are injected into fields via `@Autowired` or through setter methods. While historically popular, this approach is now generally discouraged in favor of Constructor Injection because it hides dependencies and makes testing more difficult.

  2. Aspect Oriented Programming (AOP)

    AOP in Spring allows you to modularize cross-cutting concerns. While the key unit of modularity in Object-Oriented Programming (OOP) is the class, in AOP the unit of modularity is the aspect. Common examples of cross-cutting concerns include logging, transaction management, and security checks.

    Instead of polluting your business logic with repetitive database transaction calls or security validations, you can write an Aspect that automatically intercepts specific method calls and applies the behavior. The Spring Framework uses AOP internally extensively, most notably for the `@Transactional` annotation and Spring Security's `@PreAuthorize` annotations.

    Modern Spring relies exclusively on the `@AspectJ` annotation style for configuring AOP, leaving behind the verbose XML schema-based approach of the past.
