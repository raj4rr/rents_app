In the Joined Subclass (or Table Per Subclass) strategy, each class in the hierarchy is mapped to its own table. The tables for subclasses contain only the specific columns for that subclass, plus a foreign key referencing the primary key of the superclass's table.

Modern JPA Approach: JOINED Strategy

Using JPA annotations, we use @Inheritance(strategy = InheritanceType.JOINED) on the base class. In the subclasses, we can use @PrimaryKeyJoinColumn if we want to customize the name of the joining foreign key column.


import javax.persistence.*;

@Entity
@Table(name = "PAYMENT")
@Inheritance(strategy = InheritanceType.JOINED)
public abstract class Payment {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    @Column(name = "PAYMENT_ID")
    private Long id;

    @Column(name = "AMOUNT")
    private double amount;

    // Getters and setters...
}

@Entity
@Table(name = "CREDIT_PAYMENT")
@PrimaryKeyJoinColumn(name = "PAYMENT_ID")
public class CreditCardPayment extends Payment {

    @Column(name = "CCTYPE")
    private String creditCardType;

    // Getters and setters...
}

@Entity
@Table(name = "CASH_PAYMENT")
@PrimaryKeyJoinColumn(name = "PAYMENT_ID")
public class CashPayment extends Payment {
    // Specific fields for cash payment...
}

This strategy is very clean relationally (it satisfies Third Normal Form), but it can be less performant than Single Table inheritance because retrieving a subclass requires a SQL JOIN between the superclass table and the subclass table.
