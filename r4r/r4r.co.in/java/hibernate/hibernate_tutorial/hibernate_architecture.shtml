Hibernate Architecture

The Hibernate architecture consists of multiple key components including the Session Factory, Session, Transaction, and Connection Provider. It is designed as a persistence layer to isolate the application developer from the underlying database APIs (like JDBC).

There are generally 4 layers in a Hibernate-based application: the Java Application layer, the Hibernate Framework layer, the Back-end API layer (JDBC, JTA, JNDI), and the Database layer.

This is a high-level view of Hibernate's architecture mapping to the database.

The Hibernate framework works seamlessly alongside Java APIs such as JDBC (Java Database Connectivity) and JTA (Java Transaction API).

Core Elements of Hibernate Architecture

To effectively build Hibernate applications, it is crucial to understand its core interfaces and classes:

SessionFactory (JPA equivalent: EntityManagerFactory)

The SessionFactory is a thread-safe, immutable cache of compiled mappings for a single database. It is a heavy-weight object, so typically an application will create a single SessionFactory during initialization. It also holds the second-level cache (optional) of data.

Session (JPA equivalent: EntityManager)

The Session is a single-threaded, short-lived object representing a conversation between the application and the database. It wraps a JDBC java.sql.Connection and serves as a factory for Transaction, Query, and Criteria. It holds the mandatory first-level cache of data, which guarantees object identity within the session.

Transaction (JPA equivalent: EntityTransaction)

The Transaction object specifies an atomic unit of work. It abstracts the application from underlying transaction implementations (JDBC, JTA, or CORBA).

ConnectionProvider

A factory for, and pool of, JDBC connections. It abstracts the application from the underlying DriverManager or DataSource.

TransactionFactory

A factory for Transaction instances, allowing the application to switch between transaction environments.
