One to One Mapping

A One-to-One mapping represents a relationship where one entity is associated with exactly one instance of another entity. For example, an Employee might have exactly one Address or one Passport.

Modern JPA Approach: @OneToOne Annotation

In modern Hibernate, we map these associations using the @OneToOne annotation instead of XML. Let's explore the two common ways to handle this: unidirectional and bidirectional mapping.

1. Unidirectional One-To-One Mapping

In a unidirectional mapping, only one entity knows about the relationship. For instance, the Employee knows about their Passport, but the Passport doesn't explicitly reference the Employee.

Here, the Employee table will hold the foreign key (e.g., passport_id).


import javax.persistence.*;

@Entity
@Table(name = "Employee")
public class Employee {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;

    // Define the One-to-One relationship
    @OneToOne(cascade = CascadeType.ALL)
    @JoinColumn(name = "passport_id", referencedColumnName = "id")
    private Passport passport;

    // Getters and Setters...
}

Note the use of @JoinColumn. It tells Hibernate to create a foreign key column named passport_id in the Employee table. The cascade = CascadeType.ALL tells Hibernate to automatically save the Passport when the Employee is saved.

2. Bidirectional One-To-One Mapping

In a bidirectional mapping, both entities know about each other. You can navigate from Employee to Passport, and from Passport to Employee.

To do this, we use the mappedBy attribute on the inverse side of the relationship (the side that does NOT own the foreign key).


import javax.persistence.*;

@Entity
@Table(name = "Passport")
public class Passport {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String passportNumber;

    // The 'mappedBy' attribute links this to the 'passport' field in the Employee class.
    // This tells Hibernate that the Employee entity owns the foreign key.
    @OneToOne(mappedBy = "passport")
    private Employee employee;

    // Getters and Setters...
}

When you use mappedBy, Hibernate knows it shouldn't create a second foreign key in the Passport table. It relies completely on the foreign key existing in the Employee table.
