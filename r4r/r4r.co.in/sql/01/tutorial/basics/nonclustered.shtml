NONCLUSTERED INDEX

The physical order of the rows is not the same as the index order Nonclustered indexes are typically created on columns used in joins and WHERE clauses, and whose values may be modified frequently.

SQL server creates nonclustered indexes by default when the CREATE INDEX command is given

There can be as many as 249 nonclustered indexes per table Typically, nonclustered indexes are created on foreign keys.A nonclustered index would need to be rebuilt if it is built before a clustered index

How Nonclustered Indexes Work

  1. Step First SQL sever find the rosot page from the sysindexes table.
  2. Step The search value is compared with the key values on the root page.
  3. Step The page with the highest key value less than or equal to the search value is found.
  4. Step The page pointer is followed the next lower level in the index.
  5. StepStep 3 and 4 repeated until the data page is reached.
  6. Step The rows are searched on the leaf page for the specified value. if a matched is not found, the table contains no matching rows.
  7. Step If a match is found, the pointer is followed to the data page and row-ID in the table, and the requested row is retrieved.
